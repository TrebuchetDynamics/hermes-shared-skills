## Evidence Before Operator Escalation

"Do not ask me to decide something that the repository or existing authorization
already answers." Operator involvement is the last resort. Start continuation
from current receipts, not another complete audit. Inspect accepted requirements,
Git history/diff hunks, task contracts/results, configuration and previous human
instructions before calling an unknown a human gate. Attribute the implicated
resources; shared filename or inherited dirt is not automatically an active lease.
Preserve dirty baselines, explicit exclusions and genuine overlapping work.

Distinguish missing implementation from missing authority: building a disposable
real local browser fixture is ordinary test infrastructure when the existing
Scope/Expected change admits it and it changes no production origins, credentials,
dependencies or live infrastructure. Do not repeatedly test and report that the
harness (the objective) is absent. Repair the execution pipeline if non-goal
children stop before building it: retire the incomplete invalid path with history,
not acceptance, then restore the unchanged original persistent 50-turn goal.

A worker CLI review-entry rejection does not prove no supported administrative
entry exists. Inspect the shipped authenticated dashboard Kanban PATCH review
route and native reviewer semantics. Verify it on an isolated goal50 fixture,
check original receipts and no live claim, enter REVIEW only, preserve title/body,
goal fields and receipt hashes, and observe the actual mandatory native reviewer.
Never PATCH done, invent approval, force a live claim, call private database
mutators or weaken goal/judge configuration. Use only the normally authenticated
shipped interface; any temporary loopback administrative server is task-owned and
must be stopped with socket-close evidence. Record exact entry/approval separately.
The shipped API uses X-Hermes-Session-Token from the normal loopback dashboard
bootstrap (resolve in memory; never log token/HTML); it is not Bearer auth.
Read the exact /api/plugins/kanban/tasks/{id}?board=default target: a nonexistent
/tasks list route returning 404 does not prove the plugin is unavailable.

Do not rewrite a contract after implementation merely to pass its gate. First
inspect actual source diff: a worker may have made the fix before stopping.
Inspect every stage/probe and the failure artifact's exact mode before carrying a
worker's stage label forward: a successful published probe followed by stale-detail
503 is not an initial published failure. For cloned old accepted fixtures, trace
both structural and price provenance timestamps; matching projection pointer/time
alone does not satisfy a DTO's source_snapshot_at <= derived_at <= served_at
invariant. Route coherent INSERT-time fixture corrections on the original card,
never weaken the production provenance oracle or mutate immutable history.
An already-admitted additional focused renderer test can be a compiled-browser
fixture when widget-test bindings return a no-GPU placeholder. Keep production
resources/criteria fixed, prove RED in an isolated source copy and GREEN on the
candidate; static source-order tests are not runtime discrimination.
Read the original contract before accepting a worker's assertion that a test
helper needs new authority. An unowned, non-production locator prerequisite can
have a narrow forward contract against the already-accepted read-only UI, without
rewriting the original verification slice or replaying delivered product tests.

For an explicitly authorized SAME-CARD diagnostic resumption from triage, the
shipped `kanban promote` command accepts only todo/blocked; do not invent a CLI
status flag or hand-edit rows. Read the shipped authenticated Kanban PATCH ready
route, verify no live claim, preserve the exact original contract/native50 fields
and block-loop history, prepend only current in-scope execution clarification,
read back the exact target, then observe the real worker checkpoint. A shared
native dispatcher may win the spawn race; empty `dispatch.spawned` is not failure
if the original card/readback shows its new run. Never launch a duplicate. Close
only a task-owned temporary administrative server and verify socket closure,
without stopping the project worker or existing dispatcher. This route is not
permission for blind triage retries, approval overrides or future scope expansion.

A new concrete source-bound contradiction can justify one SAME-CARD recovery;
an unchanged repeated blocker cannot. Provide the implicated callsite/branch and
what discriminating check changes the next action, not just more permission prose.
State recovery limits in native-run units, not ambiguous 'one execution' wording:
one SAME-CARD recovery per sweep still permits the assigned50-turn worker to
iterate focused fixture/test commands. Do not create a false operator permission
gate after its first failing check; an unchanged native re-block remains a stop
for the governor's sweep, not authority to weaken acceptance.
Measure migration progress read-only from current local ledger events, dedupe exact
partition identity and anchor rates to a fully covered sample window. Label these
as locally reported archival progress, not fresh S3 verification or DB reclaim.

The goal qualifier reads title/body, not board comments. If a new explicit owner
continuation changes execution instructions within unchanged admitted resources,
preserve the exact original contract in a receipt and append/prepend that owner
clarification through supported edit before recovery; retain every original
criterion verbatim, never weaken acceptance or turn exclusions into permissions.
Comments alone cannot make the goal qualifier understand current authority.
If repeated no-edit workers cannot execute ordinary admitted fixture work, route
the same project-owned task to a ready coding executor with the SAME intentional
provider/model; preflight actual auth/model readiness, preserve native50 ownership
and inspect real code/test checkpoints. Do not have the governor implement it.
Inspect prior Codex/Claude evidence scoped to the exact repository before asking
who made dirty files; a live interactive owner is a real boundary, not an abandoned
lease. Historical brainstorms and an agent's implementation do not establish the
next accepted milestone. Keep that project idle if no independent slice is clear.
Resolve shared-skill links before attempting distribution; one canonical edit may
already update all homes. Verify actual hashes instead of redundant overwrites.
A future scheduled/enabled picker is not a live workspace lease. Inspect running
cron/process/card evidence; use the supported per-profile handoff lock and active
workspace guard for an available task, rather than ask for a scheduling window.
Refresh and consume agent-owned serial continuation receipts at
`fleet-governor/blockers-reconciliation-*/pending-continuations.json` before
selecting unrelated work for that profile. Revalidate current card/body/source
and interactive/native workspace ownership. These receipts are internal task
handoffs, never a competing user blocker ledger or authority to edit excluded
resources. Preserve the current worker; only after its release admit one original
SAME-CARD continuation at a time using supported routes and observe its actual
checkpoint. Record its new run/state in that receipt so subsequent sweeps do not
repeat it. An unchanged re-block requires new evidence, not blind respawn.
Refresh Git state before blaming a changed checkout description: commits can
arrive from another actor mid-cycle. Preserve them, do not infer their source from
Git author identity, and do not claim the governor made or qualified that release.
Keep owner clarifications small enough for the installed worker-context body cap;
retain full original criteria and evidence separately rather than truncate them.
For browser CORS probes, inspect actual request semantics and current origin/fetch
metadata policy. A simple cross-origin GET need not preflight. Force a genuinely
non-simple permitted request in an isolated browser context when OPTIONS is the
criterion; never manufacture OPTIONS or forbidden Origin/Sec-Fetch headers.
An intentionally denied cross-site proxy alias is a negative control, not permission
to weaken policy. Keep same-origin proxy success, direct Server browser CORS,
remaining UI states and production qualification separate.
Do not infer missing browser preflight from Playwright page request/response events:
these may omit Chromium's actual OPTIONS. Diagnose observability first with CDP
Network events or the task-owned server wire receipt. An isolated loopback probe
can establish the capture limitation without claiming product CORS acceptance.
Inspect receipt serialization too: a same-origin no-OPTIONS assertion must not
later dereference an intentionally absent OPTIONS response.
For allowed HTTPS-origin to loopback Chromium failures, capture console and
Network.loadingFailed.corsErrorStatus before blaming Server CORS: browser
address-space permission can reject an otherwise allowed request. Reproduce on a
disposable diagnostic-only loopback server with external traffic denied; a CDP
permission command returning success is not proof that fetch was admitted. Keep
browser prerequisites separate from real Axum/UI acceptance and production policy.
Normalize case only in test-side HTTP-header lookup when CDP returns title-case
names; a lowercase-key assertion against preserved CDP headers is not a CORS gate.
For stale-state fixtures guarded by immutable publishability references, inspect
the exact trigger before escalating: a projection timestamp must match its
referenced accepted attempt. Route a complete old synthetic attempt/evidence/audit
INSERT and matching projection pointer/time through the admitted project fixture;
never update immutable history, disable triggers or weaken the oracle. Reconcile
an allowed-origin refusal with exact existing title/body authorization for isolated
local page/static origin emulation; backend responses and preflight must remain
real loopback traffic with external traffic denied.
Verify actual display/GPU prerequisites before leaving an accepted local capture
idle: device nodes and glxinfo acceleration/renderer can refute a stale hardware
blocker. Route the documented project-owned capture on changed prerequisite
evidence; hardware availability is not application-renderer or media acceptance.
For uniformly black integration captures, trace runtime-mode/placeholder selection
and compile-time define forwarding before blaming GPU availability or readback.
An integration binding can still activate a test placeholder. Route source-bound
diagnosis on the original card; a completed diagnosis is not media qualification,
and an original no-edit/one-capture contract does not permit its launcher repair.
Use an isolated named board for native50 administrative-route fixtures and archive
its fixture/card afterward. Do not assume an inherited HERMES_HOME environment
isolates the CLI: profile resolution can override it; verify the canonical DB path
before creating fixture cards. Preserve an accidentally shared blocked fixture by
archival, never project acceptance.
