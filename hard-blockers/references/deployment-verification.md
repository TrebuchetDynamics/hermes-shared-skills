# Deployment and behavioral checks

The short per-profile rule belongs in an always-loaded system-context file, not a profile-home AGENTS.md that only applies when Hermes runs from that directory. Preserve the existing profile identity and scope. Inspect the installed context-file loader before choosing an instruction path. Repository AGENTS.md edits require any tool-enforced protected-file approval; a timeout is a refusal, never permission for an alternate writer.

During distribution, discover all configured profile homes and Git roots; preserve intentional models, schedules, identity and dirty work. Install the same complete hard-blockers policy in each profile, then verify byte hashes and fresh command resolution. Fleet command/governor remain default-only. Do not modify upstream/vendor references or generate extra monorepo blocker files.

Exercise bare repo-docs on an isolated fixture with accepted intent and no user dependency. Require actual empty BLOCKERS.md creation, unchanged source/test/manifest, and a second fresh-session byte-exact no-op. Preserve command outputs and snapshots outside scratch. A successful fixture is not proof of universal adherence.

A collector must distinguish recorded candidates, structural issues and semantic verification. Keep valid active entries visible when unrelated resolved history is malformed; report the history issue. Global structural ambiguity and duplicate IDs must fail closed. Never classify missing/empty/uninspected files as evidence that historical user gates vanished.

When live project owners change blockers during rollout, reread before any maintenance. Preserve their entries, authority claims and work. Formatting corrections do not independently validate the claimed resolution, commit, push or product acceptance.
